⚙️ System Import & De-duplication Logic

  • Patient Identification: Every row is mapped by MR_No. If the patient exists in the registry, their demographics are verified and updated; no duplicate patient records are ever created.
  • Multiple Teletherapy Courses per MR No: A patient may have multiple separate treatment courses (e.g. initial course, boost, or retreatment). If a row represents a distinct course (different machine, shift, start date, or anatomical site), it is stored as an independent course linked to that same patient record.
  • Re-Import Safety: Re-importing the same file will safely detect matching existing courses and update empty fields without duplicating slots or schedule records.
  • Lookup Resolution: Consultants, Machines, Shifts, Techniques, Treatment Intents, and Simulation Categories are matched automatically. If an intent or consultant does not exist, it is safely created in reference lookups.
  • Treatment End Date: Automatically computed based on Date_of_start and No_of_fractions, excluding Sundays according to departmental scheduling rules.
